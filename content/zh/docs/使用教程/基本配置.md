# 基本配置

Fast-Https 的所有站点都由一个 JSON 配置文件描述，改完配置后重载服务即可生效。本页说明服务如何启动、配置文件在哪、整体结构是什么。

## 1 启动与托盘菜单

Windows 平台双击软件目录下的 `monitor.exe`，Linux 平台在终端执行 `./fast-https`，任务栏右下角会出现托盘图标。右键菜单提供四个操作：

| 菜单项 | 作用 |
| --- | --- |
| START | 启动 Web 服务 |
| STOP | 停止 Web 服务 |
| RELOAD | 重新加载配置文件，进程不退出 |
| QUIT | 退出托盘程序 |

## 2 默认管理页

服务启动后，浏览器访问 `http://localhost:8080/` 可以看到 Fast-Https 的默认启动页面，页面上可下载根证书 `root.crt`（用法见 [配置网站通过 HTTPS 访问](/zh/docs/使用教程/配置网站通过https访问/)）。

## 3 配置文件位置

| 平台 | 主配置文件 |
| --- | --- |
| Windows | `D:\fast-https_Windows_x86_64\config\fast-https.json` |
| Linux | `/usr/local/fast-https/config/fast-https.json` |

## 4 配置文件结构

一个最小可用的主配置文件如下：

```json
{
  "log_root": "./logs",
  "pid": "./fast-https.pid",
  "http": {
    "include": "mime.types",
    "server": [
      {
        "listen": 8080,
        "server_name": "localhost",
        "location": [
          {
            "url": "/",
            "type": "local",
            "root": "./httpdoc/www.myweb.com",
            "index": ["index.html", "index.htm"]
          }
        ]
      }
    ]
  }
}
```

顶层配置项：

| 配置项 | 说明 | 示例 |
| --- | --- | --- |
| `log_root` | 日志目录 | `./logs` |
| `pid` | 进程 PID 文件路径 | `./fast-https.pid` |
| `http.include` | 引入 MIME 类型表，或站点子配置目录 | `"mime.types"` / `["./config/conf.d"]` |
| `http.server` | 站点列表，每个元素是一个虚拟主机 | 见下 |

`server` 块的常用配置项：

| 配置项 | 说明 |
| --- | --- |
| `listen` | 监听端口；需要加密时写成 `"443 ssl"` |
| `server_name` | 该站点的域名 |
| `ssl_certificate` | 证书文件路径，仅 `ssl` 端口需要 |
| `ssl_certificate_key` | 私钥文件路径，仅 `ssl` 端口需要 |
| `location` | 路径匹配规则列表，决定请求如何被处理 |

`location` 块靠 `type` 区分处理方式：

| `type` | 含义 | 配套配置项 | 参考 |
| --- | --- | --- | --- |
| `local` | 发布本地静态目录 | `root`、`index`、`try` | [配置发布本地静态站点](/zh/docs/使用教程/配置发布本地静态站点/) |
| `proxy` | 反向代理上游服务 | `proxy_pass`、`proxy_set_header`、`proxy_cache` | [反向代理站点配置](/zh/docs/使用教程/反向代理站点配置/) |
| `rewrite` | 重定向到其他地址 | `rewrite` | [如何为网站配置重定向功能](/zh/docs/使用教程/如何为网站配置重定向功能/) |

## 5 让改动生效

保存配置文件后，点击托盘菜单 **RELOAD** 重新加载即可。若改动涉及监听端口或证书文件本身，建议先 **STOP** 再 **START**，避免端口占用。
