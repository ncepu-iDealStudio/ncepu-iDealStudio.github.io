# 解压部署

本页介绍不安装软件包、直接把 `.tar.gz` 压缩包解压后运行 Fast-Https。`.tar.gz` 是 Linux 常见的压缩格式，解压后直接得到程序和配置，不经过系统的包管理器，因此任何发行版都能用。其他方式见 [CentOS 7 安装与部署](../安装与部署/) 与 [Ubuntu 安装与部署](../ubuntu/)。

## 开始前

- 所有命令都在**服务器的终端**里执行，并且需要管理员权限。用 `root` 登录即可；如果不是 root，请在命令前加 `sudo`。
- 默认站点占用 **80 和 443** 端口。云服务器请先到控制台放行这两个端口，并确认没有被其他程序占用（第 2 步会检查）。
- 压缩包从 [Gitee Releases](https://gitee.com/ncepu-bj/fast-https/releases) 或 [GitHub Releases](https://github.com/ncepu-iDealStudio/Fast-Https/releases) 下载，文件名是 `fast-https_Linux_x86_64.tar.gz`，版本号以页面上的最新版为准。

**关于下面的「预期输出」**：每一步的输出都来自一次完整实测。那台服务器的 80 端口已被另一个站点占用，所以实测时按第 2 步的方法把 `listen` 改成了 `18080` / `18443`，示例里的验证地址也用了这两个端口。如果你的 80 / 443 空闲，把端口号换回默认值即可，输出形态完全相同。

## 1 下载并解压

下面这段一次完成「建目录 → 下载 → 解压 → 给程序执行权限」。`VER` 填 releases 页上的最新版本标签；`mkdir -p` 建目录、`tar -xzf` 解压、`chmod 755` 让程序可以运行：

```bash
mkdir -p /soft /usr/local/fasthttps
cd /soft
VER=v1.6.0
wget "https://gitee.com/ncepu-bj/fast-https/releases/download/$VER/fast-https_Linux_x86_64.tar.gz"
ls -lh fast-https_Linux_x86_64.tar.gz
tar -xzf fast-https_Linux_x86_64.tar.gz -C /usr/local/fasthttps
chmod 755 /usr/local/fasthttps/fast-https
ls -la /usr/local/fasthttps
```

**预期输出**（下载文件大小 + 解压目录，`ls -la` 节选）

```text
-rw-r--r-- 1 root root 6.5M Nov 10 19:52 fast-https_Linux_x86_64.tar.gz
total 16764
drwxr-xr-x   6 root root 4096 Nov 10 19:52 .
drwxr-xr-x. 14 root root 4096 Nov 10 19:52 ..
drwxr-xr-x   4 root root 4096 Nov 10 19:52 config
drwxr-xr-x   2 root root 4096 Nov 10 19:52 docs
-rwxr-xr-x   1 root root 17117344 Nov  6 23:26 fast-https
drwxr-xr-x   3 root root 4096 Nov 10 19:52 httpdoc
drwxr-xr-x   2 root root 4096 Nov 10 19:52 logs
-rw-rw-rw-   1 root root 17632 Nov  6 23:19 README.md
```

看到 `fast-https`（权限是 `-rwxr-xr-x`）、`config`、`httpdoc` 就表示解压和授权都成功了。

| 路径 | 说明 |
| --- | --- |
| `fast-https` | 主程序，单个可执行文件 |
| `config/fast-https.json` | 主配置，JSON 格式 |
| `config/conf.d/` | 站点配置目录，内含 `default.json` |
| `config/mime.json` | 文件类型映射 |
| `config/cert/` | 证书目录，首次启动自动生成证书 |
| `httpdoc/root/` | 默认站点目录，里面有首页 `index.html` |
| `logs/` | 运行日志 |
| `docs/usage.html`、`README.md` | 包内说明 |

用 `./fast-https config path` 可以打印配置、证书、日志与 pid 文件的实际路径（pid 文件记录进程号）：

```bash
cd /usr/local/fasthttps && ./fast-https config path
```

**预期输出**

```text
config /usr/local/fasthttps/config/fast-https.json
cert   /usr/local/fasthttps/config/cert
log    /usr/local/fasthttps/logs
pid    /usr/local/fasthttps/fast-https.pid
```

## 2 检查配置与端口

```bash
cat /usr/local/fasthttps/config/conf.d/default.json
ss -lntp | grep -E ':(80|443)\b'
```

**预期输出**（第一条：默认站点配置）

```text
{
  "listen": [80, "443 ssl h2"],
  "server_name": "localhost",
  "ssl_certificate": "./cert/localhost.pem",
  "ssl_certificate_key": "./cert/localhost-key.pem",
  "location": [
    {
      "url": "/",
      "type": "local",
      "root": "./httpdoc/root",
      "index": ["index.html", "index.htm"]
    }
  ]
}
```

`listen` 是监听端口（80 为 HTTP、443 为 HTTPS 与 HTTP/2），`server_name` 是站点对应的域名，`root` 是首页文件所在目录；带 `./` 的路径都相对于工作目录。

**预期输出**（第二条：端口被占用时）

```text
LISTEN     0      511          *:80    *:*    users:(("nginx",pid=7677,fd=8),...)
LISTEN     0      511       [::]:80 [::]:*   users:(("nginx",pid=7677,fd=9),...)
```

第二条没有任何输出表示 80 / 443 空闲；像上面这样列出进程名表示被占用。不要停掉别人的服务，改自己的配置即可：

```bash
sed -i 's|"listen": \[80, "443 ssl h2"\]|"listen": [18080, "18443 ssl h2"]|' /usr/local/fasthttps/config/conf.d/default.json
grep -n '"listen"' /usr/local/fasthttps/config/conf.d/default.json
```

**预期输出**

```text
2:  "listen": [18080, "18443 ssl h2"],
```

后面所有验证地址都要换成这两个端口。端口本来就空闲时跳过这一步。

对外提供服务时，把 `server_name` 改成实际使用的域名或 IP，并在防火墙与云平台安全组中放行相应端口。主配置里的 `security.host_check` 默认关闭，用 IP 访问不受域名校验限制。

## 3 启动服务

```bash
cd /usr/local/fasthttps
./fast-https start
```

**预期输出**

```text
{"level":"info","kind":"console","time":"2026-11-10T19:52:58.772+08:00","message":"Include config dir: /usr/local/fasthttps/config/conf.d/default.json"}
{"level":"info","kind":"console","time":"2026-11-10T19:52:58.919+08:00","message":"fast-https started in background, pid 9422, logs in /usr/local/fasthttps/logs"}
```

`started in background` 说明程序已自行转入后台，不需要再加 `&` 或 `nohup`；`pid` 每次启动都不同。首次启动会在 `config/cert/` 下生成本地 CA 与站点证书，写入 `fast-https.pid`，日志写到 `logs/` 下的 `daemon.log`、`access.log`、`system.log`、`error.log`、`safe.log`。

`./` 表示「当前目录里的这个程序」，不能省略；也**必须先 `cd` 到解压目录**，因为配置里用的是 `./conf.d`、`./httpdoc/root` 这类相对路径。

常用子命令：`start` 启动、`stop` 停止、`status` 查看运行状态、`reload` 重新加载配置、`config path` 查看路径、`site` 管理站点文件、`acme` 配置证书签发、`version` 打印版本号。完整列表见 `./fast-https --help`。

## 4 验证默认站点

```bash
cd /usr/local/fasthttps
./fast-https status
curl -sS -o /dev/null -w 'HTTP %{http_code}\n' http://127.0.0.1:18080/
curl -sk -o /dev/null -w 'HTTPS %{http_code} TLS=%{ssl_verify_result}\n' https://localhost:18443/
```

**预期输出**

```text
fast-https is running, pid 9422
HTTP 200
HTTPS 200 TLS=0
```

`running` 后面是进程号，两条 curl 的 `200` 表示请求成功；`-k` 跳过自签名证书校验，`TLS=0` 表示 TLS 连接正常。端口空闲时把地址换回 `http://127.0.0.1/` 与 `https://localhost/`。

再看端口是否真的在监听：

```bash
ss -lntp | grep -E ':(18080|18443)\b'
```

**预期输出**

```text
LISTEN   0   4096   [::]:18443   [::]:*   users:(("fast-https",pid=9422,fd=13))
LISTEN   0   4096   [::]:18080   [::]:*   users:(("fast-https",pid=9422,fd=12))
```

启动日志 `logs/daemon.log` 里也能看到同样的信息（后面还有启动横幅）：

```text
{"level":"info","kind":"console","message":"Include config dir: /usr/local/fasthttps/config/conf.d/default.json"}
{"level":"info","kind":"console","message":"fast-https started in background, pid 9422, logs in /usr/local/fasthttps/logs"}
```

如果服务器在云上，在你自己电脑的浏览器里打开 `http://<服务器公网 IP>:18080/` 可看到默认首页（用默认端口时不用带端口号）；`localhost` 只指服务器本身，不能在你的电脑上用。浏览器打开 HTTPS 时提示「证书不受信任」是正常现象，正式对外服务应配置与域名匹配的证书。

## 5 停止与重载

```bash
cd /usr/local/fasthttps
./fast-https reload
./fast-https stop
./fast-https status
```

**预期输出**

```text
{"level":"info","kind":"console","time":"2026-11-10T19:53:02.486+08:00","message":"fast-https stopped"}
Error: fast-https is not running, no pid file
```

`reload` 正常时没有输出；`stop` 打印 `fast-https stopped` 后移除 pid 文件、释放端口；最后一条 `status` 的 `Error: ... no pid file` 打印在标准错误上，是**预期结果**，说明服务确实停了。

## 6 注册 systemd 单元（可选）

解压目录里没有服务配置文件，所以默认不会开机自启。若希望开机自动启动、异常退出后自动重启，需要注册一个 **systemd 单元**。systemd 是 Linux 管理后台服务的组件，单元就是一份描述「怎么启动这个程序」的文本文件；操作它的命令是 `systemctl`。

用下面这段命令直接生成单元文件（整段复制执行即可；也可以自己用编辑器把同样的内容写进 `/etc/systemd/system/fast-https.service`）：

```bash
cat > /etc/systemd/system/fast-https.service <<'EOF'
[Unit]
Description=Fast-Https (archive deployment)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/usr/local/fasthttps
Environment=FASTHTTPS_FOREGROUND=1
ExecStart=/usr/local/fasthttps/fast-https start
ExecReload=/usr/local/fasthttps/fast-https reload
Restart=on-failure
RestartSec=2s
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
EOF
```

这条命令**没有任何输出**。可以用 `cat /etc/systemd/system/fast-https.service` 核对，内容应与上面完全一致。

其中三处不能写错：

- `WorkingDirectory` 必须是解压目录，程序按它来解析 `./conf.d`、`./httpdoc/root`、`./cert` 这些相对路径。
- `ExecStart` / `ExecReload` 必须是解压目录里 `fast-https` 的实际路径。
- `FASTHTTPS_FOREGROUND=1` 不能省略。`start` 在 Linux 上默认自行转入后台，而 systemd 的 `Type=simple` 需要程序留在前台；少这一行，主进程会立即以 `status=0` 退出，服务显示 `inactive` 且端口不监听。

写好后注册并启动：

```bash
systemctl daemon-reload
systemctl enable --now fast-https.service
systemctl is-active fast-https.service
```

**预期输出**

```text
Created symlink from /etc/systemd/system/multi-user.target.wants/fast-https.service to /etc/systemd/system/fast-https.service.
active
```

`daemon-reload` 本身没有输出；`Created symlink` 表示已设为开机自启，`active` 表示服务正在运行。再看一眼状态：

```bash
systemctl status fast-https.service --no-pager
```

**预期输出**（节选）

```text
● fast-https.service - Fast-Https (archive deployment)
   Loaded: loaded (/etc/systemd/system/fast-https.service; enabled; vendor preset: disabled)
   Active: active (running)
 Main PID: 9595 (fast-https)
   CGroup: /system.slice/fast-https.service
           └─9595 /usr/local/fasthttps/fast-https start
```

此时再请求一次，仍应得到 `HTTP 200`：

```bash
curl -sS -o /dev/null -w 'HTTP %{http_code}\n' http://127.0.0.1:18080/
```

**预期输出**

```text
HTTP 200
```

之后用 `systemctl reload fast-https.service` 重载配置、`systemctl disable --now fast-https.service` 停止并取消开机自启，日志用 `journalctl -u fast-https.service -n 30 --no-pager` 查看。`disable --now` 的输出是：

```text
Removed symlink /etc/systemd/system/multi-user.target.wants/fast-https.service.
```

此时 `systemctl is-active fast-https.service` 返回 `unknown`（或 `inactive`），表示已停止。

如果系统已经通过 [.rpm 安装包](../安装与部署/) 或 [.deb 安装包](../ubuntu/) 装过 Fast-Https，会存在同名 `fast-https.service`，注册前需先卸载安装包或改用其他单元名。

## 7 常见问题

| 现象 | 怎么处理 |
| --- | --- |
| 下载时报 404 | `VER` 写错了，去 releases 页核对最新标签 |
| `./fast-https` 提示没有权限 | 回到第 1 步执行 `chmod 755 ./fast-https` |
| 启动后 `status` 显示未运行 | 确认已 `cd` 到解压目录；用 `cat logs/daemon.log` 看报错 |
| 端口检查列出了 nginx 等进程 | 按第 2 步改 `listen`，不要停掉别人的服务 |
| curl 返回 000 或连接被拒 | 服务没起来，或验证地址里的端口没跟着改 |
| `is-active` 不是 `active` | 检查单元里 `FASTHTTPS_FOREGROUND=1` 和路径是否正确，再用 `systemctl status fast-https.service --no-pager` 看报错 |
| 自己电脑打不开页面 | 检查云安全组是否放行对应端口，且浏览器用的是服务器公网 IP |
